# MINDWEAVE — Cartography of Thought (Frontend)

A modern, topological visual workspace that transforms raw, unstructured thoughts into interactive radial mind maps. Built with React, Vite, and a custom Warm Editorial Studio design system, featuring real backend authentication integration with FastAPI and Supabase alongside an interactive mind map canvas.

---

## 1. Project Overview

MINDWEAVE is an intellectual atelier designed to help researchers, thinkers, and builders organize complex ideas into structured taxonomy. The frontend combines:
- An **editorial atelier authentication interface** connected to real Supabase & FastAPI backend endpoints.
- A **curated dashboard** for searching, filtering, and organizing topological maps.
- A **thought capture studio** supporting multi-modal input and prompt presets.
- A **radial visual editor** powered by React Flow (`@xyflow/react`) with custom nodes, pan/zoom controls, and node inspection drawers.

## 7. Environment Variable Setup

The frontend reads configuration through Vite's `import.meta.env` system.

1. Create a local `.env` file if it does not already exist by copying the provided `.env.example`:
   ```bash
   cp .env.example .env
   ```

2. Verify that `.env` contains the URL of your local FastAPI backend:
   ```env
   VITE_API_URL=http://localhost:8000
   ```

> [!IMPORTANT]
> **Security Note:** Never add Supabase service role keys, database passwords, or JWT secrets to this `.env` file. The frontend communicates with the backend exclusively via public HTTP endpoints; all credentials remain protected on the backend.

## 10. Backend Connection & Authentication Setup

### 10.1 Real Backend Authentication

The frontend authentication service in [`src/services/authService.js`](file:///C:/Users/YASH/Desktop/05.SE/Pro/MINDWEAVE-Frontend-Integration/src/services/authService.js) connects directly to the FastAPI backend running at `http://localhost:8000`:

| Endpoint | Method | Request Format | Response & Cookie Behavior |
|---|---|---|---|
| `/auth/login` | `POST` | `{"email": "...", "password": "..."}` | Returns user object; sets HttpOnly `access_token` and `refresh_token` session cookies. |
| `/auth/signup` | `POST` | `{"email": "...", "password": "...", "name": "..."}` | Registers user in Supabase; returns confirmation message. |
| `/auth/logout` | `POST` | Empty body (`credentials: 'include'`) | Instructs FastAPI to clear HttpOnly authentication cookies. |
| `/me` | `GET` | Empty (`credentials: 'include'`) | Validates active session cookie and returns user profile data. |
| `/auth/google` | `GET` | Empty | Retrieves the Supabase Google OAuth authorization URL. |

### 10.2 Cookie & Security Architecture
- **No Tokens in LocalStorage:** To mitigate cross-site scripting (XSS) risks, tokens are **never stored in `localStorage`**.
- **HttpOnly Cookies:** Authentication sessions rely on HttpOnly cookies managed by the browser and FastAPI. All API requests pass `credentials: 'include'`.
- **Session Identity:** Only non-sensitive user identity details (`{ id, email, name, avatar }`) are temporarily stored in `sessionStorage` for displaying the active user in the header drawer.

### 10.3 Real vs. Mock Features in This Build

- **Real Backend (Integrated):**
  - User registration (`POST /auth/signup`)
  - User login (`POST /auth/login`)
  - User logout (`POST /auth/logout`)
  - Session verification (`GET /me`)
  - Google OAuth redirect flow (`GET /auth/google`)
- **Client-Side Mock Data (Sprint 1 UI):**
  - Mind map listing, search, and sorting on the Dashboard (`src/data/mockData.js`)
  - Thought synthesis timing and generation steps on `/generating`
  - Mind map node graphs and node inspector details on `/editor/:id`

> [!NOTE]
> The backend server must be running independently on port `8000` for login, signup, and logout to succeed. If the backend is stopped, the frontend will display an informative connection alert.

## 11. Troubleshooting Common Errors

### 1. "Unable to connect to authentication server (http://localhost:8000)"
- **Cause:** The FastAPI backend is not running or is listening on a different port.
- **Solution:** In a separate terminal, navigate to the backend repository and start the server:
  ```powershell
  cd ..\mindmap_generator\backend
  .\venv\Scripts\uvicorn main:app --host 127.0.0.1 --port 8000 --reload
  ```
  Verify the backend is live by opening `http://localhost:8000/api/health` in your browser.

### 2. CORS Error (`OPTIONS /auth/login 400 Bad Request` or Origin Blocked)
- **Cause:** The backend's `ALLOWED_ORIGINS` setting does not include the port the frontend is running on.
- **Solution:** 
  - Ensure the frontend runs on port `3000` (or `5173`).
  - In `backend/core/config.py`, verify `ALLOWED_ORIGINS` includes:
    ```python
    ALLOWED_ORIGINS = [
        "http://localhost:3000",
        "http://localhost:5173",
        "http://127.0.0.1:3000",
        "http://127.0.0.1:5173",
    ]
    ```

### 3. "Port 3000 is in use"
- **Cause:** Another process or development server is using port 3000.
- **Solution:** Either stop the other process or run Vite on a different port:
  ```bash
  npm run dev -- --port 3005
  ```
  *(Remember to add the new port to the backend's `ALLOWED_ORIGINS` if testing authentication).*

### 4. "Invalid Email or Password" on Login
- **Cause:** Credentials entered do not match any user registered in Supabase.
- **Solution:** Switch to the **Sign up** tab on `/login`, register a new user account with a valid email and password (minimum 6 characters), then log in with those credentials.

### 5. Node.js Version Errors During `npm install` or `npm run build`
- **Cause:** Running an outdated version of Node.js (e.g., Node 14 or 16).
- **Solution:** Update to Node.js 18 or Node.js 20 LTS from [nodejs.org](https://nodejs.org/).
