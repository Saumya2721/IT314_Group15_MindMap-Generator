# api.md — Integrating the LLM Worker into the Backend

Audience: The backend engineering team (FastAPI + Supabase).  
Companion doc: [`llm.md`](./llm.md) explains how the worker functions internally.

---

## 1. Architecture Overview

The LLM module is an **asynchronous background worker** decoupled from PostgreSQL and Supabase:
- **No Database Connection**: The worker does not touch PostgreSQL, has no `asyncpg` dependency, and has no database credentials.
- **Backend Owns Persistence & Auth**: The FastAPI backend owns PostgreSQL, user authentication, and Supabase Row Level Security (RLS).
- **Communication Contract**:
  1. **Inbound**: Backend enqueues a typed `GenerationRequest` over Redis.
  2. **File Transfer**: Backend passes short-lived signed Storage URLs (`FileRef`). Worker downloads raw bytes over HTTPS.
  3. **Outbound**: Worker invokes internal HTTP POST callbacks (`/internal/jobs/{id}/progress`, `/complete`, `/fail`) authenticated with a short-lived Bearer token.
- **Vector Isolation**: Per-map Pinecone namespaces (`namespace=str(map_id)`).

```
[React Frontend Client]
       │  (1) Upload files directly to Supabase Storage (or via FastAPI)
       │  (2) POST /api/maps/{id}/generate (with topic, ideas, storage file keys)
       ▼
[FastAPI Backend] ── owns Postgres, enforces JWT/RLS ─────────────────────────┐
       │ (3) Generates signed URLs for files                                   │
       │ (4) Enqueues GenerationRequest to Redis (ARQ)                         │
       ▼                                                                       │
[ARQ Worker] (this codebase)                              [HTTP POST Callback] │
       │                                                  (Progress/Complete)  │
       ├─► Pulls job from Redis Queue                                          │
       ├─► Downloads file bytes from signed Storage URLs                       │
       ├─► Extracts text & chunks seed data                                    │
       ├─► Embeds & upserts to Pinecone (namespace = map_id)                   │
       ├─► Executes LangGraph pipeline (Ingest -> Route -> Retrieve -> Gen)   │
       └─► Sends validated NodeDraft/EdgeDraft result ─────────────────────────┘
```

## 2. Inbound Contract: Enqueueing Jobs to Redis

The worker runs using [ARQ](https://arq-docs.helpmanual.io/) over Redis. To enqueue a job from FastAPI, use `arq.create_pool()`:

```python
import uuid
from arq import create_pool
from arq.connections import RedisSettings


# Enqueue helper inside FastAPI:
async def enqueue_generation_job(redis_pool, request_payload: dict):
    await redis_pool.enqueue_job(
        "generate_mindmap",
        request_payload,
        _job_id=str(request_payload["job_id"]),
    )
```

### Inbound Payload Schema: `GenerationRequest`

All schemas are defined in [`contracts/models.py`](./contracts/models.py).

```jsonc
{
  "job_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d", // UUID: generation_jobs.id
  "map_id": "c3d4e5f6-a7b8-9012-cdef-1234567890ab", // UUID: mind_maps.id
  "job_type": "generate",                           // "generate" | "regenerate_full" | "regenerate_node"

  // Fresh generation (US-03)
  "topic": "Quantum Computing",                     // string | null
  "ideas": "Qubits, Superposition, Entanglement",   // string | null
  "files": [                                        // list of files already in Storage
    {
      "file_name": "quantum_intro.pdf",
      "mime_type": "application/pdf",
      "url": "https://<supabase-project>.supabase.co/storage/v1/object/sign/seed-assets/...", // Signed URL (valid 15-30m)
      "storage_key": "user_123/map_456/job_789/quantum_intro.pdf"
    }
  ],

  // Full regeneration (US-04) — seed text is reconstructed from Pinecone automatically
  "regeneration_instruction": null,                 // string | null (e.g. "Focus more on quantum error correction")

  // Optional detail level
  "detail_level": null,                             // "overview" | "balanced" | "detailed" | null (inferred if null)

  // Internal callback security
  "callback_base_url": "https://api.yourdomain.com",// Internal or backend base URL
  "callback_token": "job-scoped-secret-token"       // Short-lived token generated by backend for this job
}
```

## 3. Outbound Contract: Backend Callback Endpoints

The backend exposes internal HTTP callback endpoints authenticated with `Authorization: Bearer <callback_token>`.

### 3.1 Pre-Flight Check: `GET /internal/jobs/{job_id}`

Called by the worker before starting generation to ensure the job was not already completed (e.g. after an ARQ retry following a late network callback):
* **Response (`200 OK`):**
```json
{
  "id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "status": "pending",
  "already_terminal": false,
  "receipt_id": null
}
```
If `already_terminal` is true, the worker returns immediately with `{ "already_processed": true }` to avoid repeating expensive LLM generation work.

### 3.2 Progress Notification: `POST /internal/jobs/{job_id}/progress`

Called at key milestones during generation.

* **Payload:**
```json
{
  "progress_percent": 40
}
```
* **Milestones Emitted:**
  - `10`: Seed text ingested & embedded into Pinecone.
  - `20`: Routing decision complete (detail level resolved, tools selected).
  - `40`: Context retrieval and reranking complete.
  - `70`: Candidate mind map draft produced by LLM.
  - `85`: Graph structural validation passed (or retrying).
  - `100`: Complete.
* **Backend Action**: Update `generation_jobs.progress_percent = progress_percent` in PostgreSQL (which pushes live updates to the frontend via Supabase Realtime).
* **Fault Tolerance**: If the progress endpoint returns 5xx or times out, the worker **logs the warning and continues**. Progress failures never abort generation.

---

```jsonc
      "id": "e0b9c51a-7b8c-4f1e-9a2b-3c4d5e6f7a8b", // Generated real UUID

      "background_color": "#1E293B",
      "text_color": "#F8FAFC"

      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "source_node_id": "e0b9c51a-7b8c-4f1e-9a2b-3c4d5e6f7a8b",
      "target_node_id": "f1c0d62b-8c9d-502f-ab3c-4d5e6f7a8b9c",

    {
      "asset_type": "text",

  "rejected_files": [],
  "tool_call_log": []

```

* **Backend Actions**:
  1. In a single transaction:
     - If regeneration: delete or replace prior nodes/edges for this map.
     - Insert `nodes` and `edges` rows with `map_id` and the provided UUIDs.
     - Insert rows into `seed_assets`.
     - Update `generation_jobs`: `status = 'completed'`, `progress_percent = 100`, `completed_at = now()`.
  2. Insert an assistant summary record into `chat_messages` (e.g. *"Generated mind map with 12 nodes and 11 edges (balanced detail)."*).
  3. Respond with HTTP `200 OK`.

---

### 3.3 Job Failure / Rejection: `POST /internal/jobs/{job_id}/fail`

Called when generation cannot be completed.

* **Payload:**
```jsonc
{
  "job_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "map_id": "c3d4e5f6-a7b8-9012-cdef-1234567890ab",
  "status": "failed", // or "rejected"
  "seed_assets": [],
  "rejected_files": [
    { "file_name": "corrupt.pdf", "reason": "No extractable text layer found" }
  ],
  "error": {
    "stage": "validate", // e.g. "intake", "generate", "validate", "unknown"
    "error_type": "ValidationFailure",
    "message": "Generation failed after retries: Found 2 root nodes",
    "retryable": true
  }
}
```
* **Status Distinction**:
  - `rejected`: The job never ran because inputs were unusable (e.g., all uploaded files failed parsing, topic was empty, or regenerating a map that has no prior seed). `retryable` is `false`.
  - `failed`: The pipeline ran but failed (e.g., LLM produced invalid JSON after max retries, or external provider outage). `retryable` is `true`.
* **Backend Actions**:
  1. Update `generation_jobs`: `status = payload.status`, `error_message = payload.error.message`, `completed_at = now()`.
  2. Insert an assistant failure message in `chat_messages`.
  3. Respond with HTTP `200 OK`.

## 4. Recommended FastAPI Route Sketch (Backend Side)

Here is how the backend routes connect to this architecture:

```python
import uuid
from fastapi import APIRouter, Depends, HTTPException, status
from pydantic import BaseModel

router = APIRouter(prefix="/api/maps", tags=["maps"])


class GenerateRequest(BaseModel):
    topic: str | None = None
    ideas: str | None = None
    file_keys: list[str] = []
    detail_level: str | None = None


@router.post("/{map_id}/generate", status_code=status.HTTP_202_ACCEPTED)
async def generate_map(
    map_id: uuid.UUID,
    body: GenerateRequest,
    user_id: uuid.UUID = Depends(get_current_user_id),
    db=Depends(get_db),
    redis=Depends(get_redis_pool),
    storage=Depends(get_storage_client),
):
    # 1. Verify user owns the mind map (under RLS)
    await assert_map_owner(db, map_id, user_id)

    # 2. Prevent concurrent runs on the same map
    active_job = await get_active_job(db, map_id)
    if active_job:
        raise HTTPException(
            status_code=409, detail="A generation job is already running for this map."
        )

    # 3. Create generation_jobs row (status='pending')
    job_id = uuid.uuid4()
    await create_job_record(db, job_id=job_id, map_id=map_id, job_type="generate")

    # 4. Generate signed URLs for any files uploaded to Storage
    file_refs = []
    for key in body.file_keys:
        signed_url = await storage.create_signed_url("seed-assets", key, expires_in=1800)
        file_refs.append(
            {
                "file_name": key.split("/")[-1],
                "mime_type": guess_mime_type(key),
                "url": signed_url,
                "storage_key": key,
            }
        )

    # 5. Mint a short-lived token for callback authentication
    callback_token = mint_job_token(job_id)

    # 6. Enqueue GenerationRequest to Redis
    payload = {
        "job_id": str(job_id),
        "map_id": str(map_id),
        "job_type": "generate",
        "topic": body.topic,
        "ideas": body.ideas,
        "files": file_refs,
        "regeneration_instruction": None,
        "detail_level": body.detail_level,
        "callback_base_url": "https://api.yourdomain.com",
        "callback_token": callback_token,
    }
    await redis.enqueue_job("generate_mindmap", payload, _job_id=str(job_id))

    # 7. Return 202 immediately with job_id so frontend can poll or subscribe
    return {"job_id": job_id, "status": "pending"}
```

## 5. Security & Isolation Model

1. **Supabase RLS Protection**: The backend verifies user JWTs and executes queries against Postgres under RLS or with explicit `WHERE user_id = :uid` checks. The worker never receives user credentials.
2. **Worker Isolation**: The worker is completely isolated in its own network container/process. It only needs access to:
   - Redis queue.
   - Pinecone API.
   - LLM & Embedding provider APIs.
   - Internal callback endpoint.
3. **Callback Authentication**: The `callback_token` is unique per job and minted by the backend. The worker can only invoke callbacks for the specific `job_id` passed in its payload.
4. **Vector Namespace Isolation**: Pinecone queries and upserts use `namespace=str(map_id)`. Vector lookups from Map A can never read chunks from Map B.
