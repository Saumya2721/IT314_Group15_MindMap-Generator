# Master AI Agent Guidelines (`AGENT.md`)

This is the definitive reference manual for any AI coding assistant modifying the **Mind Map Generator from Raw Ideas** codebase. Read and uphold these non-negotiable architectural invariants, security rules, and verification checklists before proposing or executing code changes.

---

## 1. Monorepo Architecture & Subsystem Boundaries

The codebase is organized into four strictly decoupled workspaces:

```text
IT314_Group15_MindMap-Generator/
├── backend/                  # FastAPI REST API, Supabase auth, Postgres asyncpg, storage
├── llm/                      # Detached ARQ background worker, LangGraph engine, Pinecone RAG
├── frontend/                 # React 18 SPA, Vite, @xyflow/react canvas, warm editorial UI
├── supabase/                 # PostgreSQL migrations, RLS policies, storage bucket config
├── docs/                     # Course specifications, requirements, and engineering rules
├── contracts/                # Shared wire contracts (symlinked/mirrored into backend & llm)
└── AGENT.md                  # This master agent instruction document
```

### System Boundaries
- **Backend owns persistence**: Only `backend/` connects to PostgreSQL and Supabase GoTrue Auth.
- **Worker is detached**: `llm/` receives jobs exclusively via Redis (`GenerationRequest`), processes text/multimodal assets, and reports back via authenticated HTTP callbacks (`/internal/jobs/{id}/...`). The worker **never** talks to PostgreSQL directly.
- **Frontend is an interactive studio client**: `frontend/` calls backend REST endpoints via `apiClient.js` proxies, rendering the mind map on an interactive React Flow canvas with live editing, outline navigation, snapshot rollback, and topological chat assistant.

## 2. Non-Negotiable Architectural & Security Invariants

### Invariant 1: Dual-Defense Authentication Protocol & PKCE OAuth
- **Cookie + Header Hybrid**: The backend accepts both `Authorization: Bearer <token>` and `access_token` HttpOnly cookies.
- **No `localStorage` JWTs**: Frontend code must **never** write raw JWT tokens to `localStorage` (XSS vulnerability). Active session tokens are stored in active tab memory / `sessionStorage`, while long-term session persistence is anchored by HttpOnly cookies.
- **Silent Refresh**: On 401 Unauthorized, frontend automatically attempts `POST /auth/refresh` using the HttpOnly refresh token cookie before rejecting requests.
- **PKCE OAuth Verifier Persistence**: In Google OAuth, the `code_verifier` generated by Supabase is persisted in an HttpOnly cookie (`oauth_code_verifier`) and tab-scoped `sessionStorage`. `POST /auth/google/callback` extracts this verifier to fulfill the PKCE exchange without losing state.
- **SPA Proxy Bypass**: Vite dev proxy must never proxy `/auth/callback` to the backend as a 404; it serves `index.html` for client-side routing.

### Invariant 2: Database Schema & Supabase Storage Cleanup
- **Column Correctness**: The table `public.seed_assets` defines the column as **`storage_key`** (type `TEXT`). Column `storage_path` does **not** exist.
- **Snapshot Schema Alignment**: The table `public.map_snapshots` stores graph snapshots in JSONB columns (`graph`, `nodes_snapshot`, `edges_snapshot`) with version numbering (`version_no`). Endpoints must transparently serialize `nodes_count`, `edges_count`, and `reason`.
- **Transactional Cascade Safety**: `delete_map_storage_files` must clean up files in bucket `seed-assets` **before** executing `DELETE FROM public.mind_maps`.
- **Fail-Safe Abortion**: If Supabase Storage cleanup fails, `delete_map_storage_files` must raise an error and abort with `502 Bad Gateway`. The database row must never be deleted if storage cleanup fails, preventing orphaned binary objects.

### Invariant 3: Generation Job Lifecycle State Machine (`chk_generation_job_lifecycle`)
- PostgreSQL table `public.generation_jobs` enforces strict status transitions:
  - Jobs that have started (`started_at IS NOT NULL`) **cannot** have terminal status `rejected`. They must be set to `failed`.
  - Only jobs that never started (`started_at IS NULL`) can be set to `rejected`.
- Internal callback handlers in `backend/app/routes/internal.py` must strictly uphold this rule.
- Callback failure recovery: If an internal HTTP callback fails, the worker must catch the exception, retry, and ensure the job in PostgreSQL does not hang in `running`.

### Invariant 4: Topological DAG Integrity & Edge Safety
- **Exactly One Root (DR-02)**: The synthesized mind map must have exactly one root node (in-degree = 0).
- **DAG Cross-Links Preserved**: Mind maps are directed acyclic graphs, **not** strict hierarchical trees. Cross-links (nodes with multiple parents) are deliberate and must never be pruned or collapsed.
- **Full Reachability (DR-03)**: Every non-root node must be reachable via directed edges originating from the central root node.
- **Unique IDs (DR-01)**: All node identifiers must be unique.
- **No Self-Loops & Cycle Detection**: Edge creation and route update (`PATCH /api/maps/{id}/edges/{edge_id}`) must reject self-loops (`source == target`) and run BFS cycle detection (`check_edge_creates_cycle`).
- **Root Node Protection**: Action proposals in chat and canvas mutations must reject deleting the central root node (`node_type == 'root'`).

### Invariant 5: Regeneration Safety & Non-Destructive Cancellation (P0 Invariant)
- **Never Delete Existing Maps on Regeneration**:
  - Initial generation from scratch may clean up its empty placeholder draft if generation fails or is canceled.
  - Full map regeneration or branch regeneration (`isRegeneration === true` or existing nodes count > 0) **must never** delete the mind map or its existing graph on failure or cancellation.
- **Polled Job Ref Guard**: Any job polled from `location.state.jobId` in `GeneratingPage.jsx` must be guarded by `polledJobIdRef` to prevent infinite polling loops on component re-renders.
- **Canonical Editor Redirect**: Upon job completion (`job.status === 'completed'`), the client must navigate to `/editor/${targetMapId}` with `{ replace: true, state: { mode: 'editor' } }` to ensure URL and view state are synchronized.

### Invariant 6: Optimistic Concurrency Control (OCC)
- Graph persistence (`PATCH /api/maps/{id}/graph`) requires `expected_version`. If a concurrent update bumped the map version, the backend returns `409 Conflict`.
- Upon restoring a snapshot (`POST /api/maps/{id}/snapshots/{id}/restore`), the client must update its internal `mapVersionRef` to the newly returned version number to prevent 409 errors on subsequent edits.

### Invariant 7: Sprint Delivery Status & Scope Boundaries
- **Sprint 1 Delivered**: Thought capture, seed upload, background worker synthesis, and read-only graph visualization.
- **Sprint 2 Delivered**: Interactive canvas with node dragging & Cartesian coordinate persistence, node & edge CRUD, relationship binding, partial branch regeneration, version history & rollback, chat action proposals, multi-format export (PNG/PDF/Markdown), and prompt token budgeting.
- **Sprint 3 Delivered**: Role-based admin oversight (`profiles.role`, user management, aggregate analytics, audit log), long-term agent memory (`agent_memories` table, post-turn proposal, token-budgeted injection, GDPR export), LangSmith end-to-end tracing, automatic context & dynamic token budgeting (`ContextBudgetManager` with provider-aware limits and priority pruning), multi-source ingestion (DOCX, PPTX, SSRF-guarded URL seeds), cloud vision integration (Google Gemini Flash with Tesseract fallback), live research tools (Wikipedia, Page Reader, Scholar), research agent subgraph with Redis caching, runtime pipeline configuration API (`/admin/config`, `/internal/config`), and deterministic Top-to-Bottom tree layout.
- **Scope Adjustments**: Real-time collaborative multi-user editing (presence/SSE) and folder refactor were deferred/scratched in Sprint 3 in favor of hardening core platform administration, memory, and LLM orchestration.

### Invariant 8: Role-Based Admin Oversight & Zero-Content-SELECT Boundary (S3-DB1, S3-BE1)
- **Role Enforcement**: User role is persisted in `profiles.role` (`user` or `admin`, default `user`). All administrative routes (`/admin/*`) strictly enforce the `require_admin_role()` dependency.
- **Zero Content SELECT Invariant**: Admins have **zero SELECT permissions** on user content tables (`mind_maps`, `nodes`, `edges`, `chat_messages`, `agent_memories`). Admin analytics are computed exclusively via aggregate database views (`admin_stats_view`).
- **Audit Logging**: Every administrative action (suspension, unsuspension, deletion, config changes) must write an immutable record to `admin_audit_log` with actor ID, target user ID, action, and JSONB metadata.

### Invariant 9: Long-Term Memory Lifecycle & User Sovereignty (S3-DB2, S3-BE4, S3-L3)
- **Ownership Isolation**: `agent_memories` rows belong exclusively to the creating user (`user_id`). Users can inspect, edit, disable, or delete their memories at `/memory`.
- **Worker Proposal Write Path**: The LLM worker never writes directly to the database; it sends candidate memories via `POST /internal/memory/propose`, which enforces validation, deduplication, importance decay, and per-user limits (500 rows).
- **Token Budget Ceiling**: At prompt assembly time, retrieved top-$k$ memories must never exceed 10% of the active provider context budget. If memory retrieval fails or times out, generation proceeds without memories (graceful degradation).

### Invariant 10: Provider-Aware Context Budgeting & Dynamic Pruning Hierarchy (S3-L7)
- **`ContextBudgetManager` Rule**: All prompt assembly must dynamically allocate token budgets across system prompt, seed summary, long-term memories, RAG chunks, and conversation turns based on active provider ceilings (e.g. Groq 8k/6k input ceiling, Qwen OTPM clamp, Gemini Flash 32k/128k).
- **Strict Pruning Order**: When assembled context exceeds provider ceilings, pruning must execute strictly in this order:
  1. Lowest-scoring RAG context chunks.
  2. Oldest conversational turns beyond the sliding window.
  3. Dense external tool payloads from Wikipedia, Page Reader, or Scholar.
  System instructions and active seed core focus are **never** pruned.

### Invariant 11: Multi-Source Ingestion, Vision Extractor Fallback & SSRF Defense (S3-R1, S3-L6, S3-T2)
- **Extractor Registry**: All file uploads route through `ingestion.extractors.registry.get_extractor_for_mime()`.
- **Vision Model Fallback Chain**: Images are extracted using Google Gemini Flash (`gemini-3.8-flash`) by default. If the API is unreachable, empty, or unconfigured, it must fall back seamlessly to local `pytesseract`.
- **SSRF Guard on URL Seeds & Page Reader**: URL seeds and Page Reader tools must validate target hostnames against public IP ranges, reject private/loopback/cloud-metadata addresses (e.g. `127.0.0.1`, `169.254.169.254`, `10.0.0.0/8`), enforce $\le 3$ redirects, $\le 1\text{ MB}$ response size, and a 5-second timeout.

### Invariant 12: Distributed Redis Rate Limiting & Tool Policy Limits (S3-BE5, S3-L1)
- **Redis Limiter**: Quotas for generation requests, chat turns, and memory proposals must be tracked in Redis using sliding-window counters (`app/services/rate_limiter.py`).
- **Tool Policies**: External research tools (Tavily, Wikipedia, Scholar) must enforce per-call timeouts ($\le 5\text{s}$) and bounded total research budget ($\le 10\text{s}$) inside the research subgraph.

### Invariant 13: Deterministic Top-to-Bottom Tree Geometry & React Flow Handles
- **Vertical Tree Direction**: Mind maps flow vertically top-to-bottom ($Y$ advances by tree level with level step $\Delta y = 200.0$, starting from root apex at $y=80.0$).
- **Parent Centering**: Parent nodes are centered horizontally above the bounding span of their children ($\text{pos\_x} = \frac{\text{child}_1.\text{pos\_x} + \text{child}_k.\text{pos\_x}}{2}$).
- **React Flow Handles**: All edges must connect from parent handle `sourceHandle: 'source-bottom'` to child handle `targetHandle: 'target-top'` to ensure clean vertical bezier routing.
- **Incremental Placement**: New nodes appended during chat proposals are placed at level $\text{parent}.\text{pos\_y} + 200.0$ to the right of any existing siblings with collision avoidance.

## 3. Monorepo Execution & Tooling Nuances

- **Directory Roots for Pytest**: Each Python workspace sets its own `pythonpath` in `pyproject.toml`. Pytest must always be executed from the workspace root:
  - Backend: `Set-Location "backend"; python -m pytest tests -q`
  - LLM: `Set-Location "llm"; python -m pytest tests -q`
- **Mypy Path Resolution**:
  - In `backend/pyproject.toml`: `mypy_path = ["app", "."]` is required because code imports `from core.config import settings`.
  - In `llm/pyproject.toml`: `mypy_path = "mindmap_llm"` is required.
- **FastAPI Idiom vs Ruff B008**:
  - FastAPI dependency injection (`= Depends(...)`, `= Form(...)`, `= File(...)`) triggers Ruff `B008` unless explicitly ignored. `B008` is ignored in `backend/pyproject.toml`.
- **Preserve Existing Comments & Docstrings**: Do not strip or alter unrelated comments, docstrings, or license headers.

## 5. LangSmith Observability & Quality-Gate Evaluation

### Environment Variables
Set these variables in `llm/.env` (never commit real credentials):
```dotenv
LANGSMITH_TRACING=true
LANGSMITH_ENDPOINT=https://apac.api.smith.langchain.com
LANGSMITH_API_KEY=ls-...             # from https://smith.langchain.com → Settings → API Keys
LANGSMITH_AGENT_ID=mindweave-dev     # project name in dashboard
LANGSMITH_AGENT_ENVIRONMENT=local
```

### Architecture & Instrumentation
- `configure_langsmith()` runs once at worker process initialization in `llm/mindmap_llm/worker/settings.py::on_startup`.
- When `LANGSMITH_TRACING=false` (or unset), tracing is a complete no-op (zero network overhead, safe fallback).
- Auto-instrumentation via LangGraph captures all graph transitions (`ingest`, `classify_routing`, `retrieve`, `generate`, `validate`).
- Explicitly instrumented spans (`@trace_span`):
  - `generate_mindmap`: Root chain span for full generation jobs
  - `regenerate_mindmap` & `regenerate_full`: Spans for full map regeneration
  - `regenerate_node_task` & `regenerate_node`: Spans for node-level regeneration
  - `chat_turn_task`: Root span for conversational turns
  - `generate_node` & `generate_branch_node`: LLM node synthesis spans
  - `plan_research_queries`: Sub-query planning LLM span
  - `groq_generate`: Raw LLM completions with token usage metadata
  - `reconstruct_seed_from_namespace`: Vector store seed reconstruction span

### Dashboard Projects
- **Dev environment**: `LANGSMITH_AGENT_ID=mindweave-dev`
- **Prod environment**: `LANGSMITH_AGENT_ID=mindweave-prod`

### Quality-Gate Dataset
Run the one-time benchmark seed loader:
```powershell
Set-Location "llm"
python tests/evaluation/langsmith_dataset.py
```
This uploads the S2-L13 benchmark cases into the `mindweave-eval-seeds` dataset on LangSmith for tracking generation quality gates.
